# 证据与归属规则

## 1. 证据类型

| 类型 | 使用方式 |
|---|---|
| yZz 原话 | 判断目标、批准、否决、纠正和范围的最高来源。 |
| 第三方原话 | 只证明第三方提出过该内容，不证明 yZz 批准。 |
| Agent 解释 | 用于说明机制或形成建议，不具有用户决策权。 |
| Agent 推论 | 必须标明推论及依据，不能写成用户事实。 |
| 外部原始资料 | 用于核验外部事实，记录日期、版本和适用范围。 |
| 当前项目文件 | 用于了解现状；文件受到质疑时不能自证，需要回查历史。 |

## 2. 时间顺序

1. 按消息发生顺序读取完整相关历史。
2. 查找后文对前文的纠正、否决、替代或范围缩小。
3. 使用最后一次有效用户表态形成当前判断。
4. Agent 后来的总结不能覆盖用户原话。

## 3. 批准与归属检查

对每个准备写入最终策略的承重陈述，检查：

1. 陈述内容是什么。
2. 谁最先提出。
3. yZz 是否明确批准该具体内容。
4. 批准是否只针对写入、执行、内容或验收中的某一项。
5. 后文是否发生纠正或否决。
6. 当前文件是否准确保留归属。
7. 来源链接是否指向实际产生该内容的记录。

## 4. 历史记录限制

会话归档可能跳过被改写分支、工具输出、后台任务和压缩前历史。归档元数据必须与正文一起读取。关键信息缺失时，可以回查本地源 JSONL；不能用 Agent 记忆补全。

历史记录保持原样。历史中的错误中间答案用于证明发生过什么，不作为当前策略依据。

## 5. 用户事实

用户经历、能力、设备、目标和认知状态只允许引用用户明确自述。Agent 使用类比、教学假设或背景推断时，不得把相关工具、经历或熟练程度写成用户事实。
