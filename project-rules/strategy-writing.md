# 最终策略编写规则

## 1. 文件属性

`final-strategy/` 是完整、最高标准的项目最终策略。读者包括 yZz、31415 和未来参与者。文件结构需要支持多人阅读和分主题编辑。

`final-strategy/README.md` 是唯一入口。只有其清单中列出的文件属于权威策略正文。

## 2. 内容边界

最终策略可以包含：

- 用户已经批准的产品目标、范围、架构和工作顺序。
- 经核验并注明日期与来源的外部事实。
- 已批准实验的状态和已验收结果。
- 对已批准内容的准确、必要说明。

最终策略不得包含：

- 未获批准的 Agent 候选设计。
- 用户明确否决或后来取代的内容。
- 聊天过程、Agent 自我评价或用户画像推断。
- 以用户决定形式呈现的第三方建议。
- 当前 TODO 的过程记录。

尚未批准的讨论保留在来源记录中。只有 yZz 明确批准记录为当前任务后，相关内容才能进入 `current.md`；只有 yZz 批准为策略后，相关内容才能进入最终策略。

## 3. 修改流程

1. 确定要修改的策略对象。
2. 阅读相关策略文件、`sources.md`、审批规则和原始记录。
3. 找到最后一次有效用户表态。
4. 区分用户原话、第三方原话、外部事实、Agent 解释和 Agent 推论。
5. 检查后文是否纠正、否决或缩小了范围。
6. 只写入获得批准的内容；对外部事实注明核验日期。
7. 检查训练与推理、单位、尺度、输入、输出和时序是否明确。
8. 更新 `sources.md` 中的来源映射。
9. 检查所有内部链接和台账对应位置。

## 4. 文件分工

| 文件 | 内容 |
|---|---|
| `README.md` | 文件身份、阅读顺序、策略摘要和台账关系。 |
| `product-and-boundaries.md` | 产品需求、项目范围、依赖与贡献边界、兼容和合规边界。 |
| `architecture-dataflow.md` | L1/L2/L3、数据族、训练、推理和接口约束。 |
| `validation-risk-status.md` | 已批准实验、判据、状态、风险和监控。 |
| `sources.md` | 来源地图、适用范围和归属边界。 |

## 5. 旧文件迁移

根目录 `final-strategy.md` 在迁移阶段只作为指向 `final-strategy/README.md` 的临时入口，不复制策略正文。有效项目引用迁移完成后删除该临时入口。历史记录保持原样。
