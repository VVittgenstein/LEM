# 最终策略编写规则

## 适用范围

本项目最终策略固定存放在 [final-strategy/](../final-strategy/)。

策略承担完整、最高标准的项目方案职责；目录内部的文件、名称、章节、数量和组织方式由项目决定。

## 规则

1. 只有 yzz 明确同意或批准的具体内容才能作为已确定策略写入。批准后 Agent 自动同步该内容，无需再次询问相同写入。
2. 批准只适用于明确的对象和范围。
3. yzz 原话、第三方意见、Agent 理解分别归属；来源保存在适合项目的位置。
4. 策略记录整体目标与方案，current 记录获准任务及完整进展。
5. 新部署采用 yzz 已明确的内容。AGENTS 和本规则只使用目录入口。

## 操作与记录

修改前读取原策略和相关来源，保留仍有效的要求。获准内容写入后同步 final-strategy 内相关内容与已授权引用；涉及 AGENTS 的修改另按其起草与文字确认流程处理。历史原文保持。

本项目额外编写约定：最终策略面向 yZz、31415 和未来参与者阅读，文件结构需要支持多人阅读和分主题编辑。以下细则沿用 2026-09-29 迁移前的策略编写规则：

1. 最终策略可以包含：用户已经批准的产品目标、范围、架构和工作顺序；经核验并注明日期与来源的外部事实；已批准实验的状态和已验收结果；对已批准内容的准确、必要说明。
2. 最终策略不得包含：未获批准的 Agent 候选设计；用户明确否决或后来取代的内容；聊天过程、Agent 自我评价或用户画像推断；以用户决定形式呈现的第三方建议；当前 TODO 的过程记录。
3. 尚未批准的讨论保留在来源记录中。
4. 修改流程：确定要修改的策略对象；阅读相关策略文件、策略目录中的来源映射、[权限与批准规则](authority-and-approval.md)、[证据与归属规则](evidence-attribution.md)和原始记录；找到最后一次有效用户表态；区分用户原话、第三方原话、外部事实、Agent 解释和 Agent 推论；检查后文是否纠正、否决或缩小了范围；只写入获得批准的内容，对外部事实注明核验日期；检查训练与推理、单位、尺度、输入、输出和时序是否明确；更新策略目录中的来源映射；检查所有内部链接和台账对应位置。
5. 根目录 `final-strategy.md` 在迁移阶段只作为指向 `final-strategy/` 的临时入口，不复制策略正文。有效项目引用迁移完成后删除该临时入口。历史记录保持原样。
