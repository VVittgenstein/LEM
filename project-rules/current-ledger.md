# 当前任务记录规则

## 适用范围

适用于 current 的索引、完整任务记录及结束后的整项归档。

## 规则

1. 新任务只有 yzz 明确批准记录后才能进入 current，条目保留批准依据。
2. 每项按 yzz 原话、Agent 认为的任务、状态演进三部分记录。原话逐字保存并注明来源；Agent 理解保持自己的归属，缺少原始来源时如实说明。
3. Agent 日常自动只在已有任务的状态演进末尾追加可核查事实，注明【Agent 自动追加】；允许同步索引中的事实进展摘要。
4. 每项任务在一个文件内完整展示生命周期。
5. 任务范围过大时可提出划分建议。yzz 批准后才能调整或建立条目，原任务历史完整保留。
6. 只有 yzz 确认结束后才能将完整任务文件移入 archive，保留编号和全部正文。
7. 索引保持编号、任务、状态、简要进展、记录五列。状态中的批准、验收、完成等判断须有对应的 yzz 表态。

## 操作与记录

先读索引和相关任务。追加实际动作、结果、产物位置、等待条件或已确认问题后，可将索引简要进展同步为相同事实。大量日志和产物可链接其实际位置，但每次任务进展的记录仍保留在任务文件。

归档时整项移动并更新引用。

本项目约定：台账由 `final-strategy/` 与 `current/` 共同组成；current 不负责定义新的项目架构或战略。以下细则沿用 2026-09-29 迁移前的 `current.md` 编写规则：

1. 原话保持逐字内容，不改写语法、术语或拼写；以引用块保存，其后另起一行写“来源：”及记录文件和位置；多次原话共同限定任务时，按时间顺序列出；Agent 解释不得混入该部分。
2. “Agent 认为的任务”记录 Agent 当时如何理解和操作化任务，可以包含范围、预期结果、依赖和未知项。它可能存在错误，因此必须与用户原话分开。Agent 不得在该部分声称用户已经理解、批准或接受某项 Agent 推论。
3. 状态演进按事情发生顺序追加，每条以日期开头。一次未完成、等待外部条件、发生阻塞或后续继续执行时，保留完整时间顺序。
4. Agent 可以自动追加：已执行的动作；命令、测试或实验的可验证结果；产物路径；当前等待的对象或条件；已确认的阻塞原因；原批准范围内的下一步状态。
5. Agent 不得自动追加：新任务、范围或优先级；对用户意图的解释；对任务目标的重新定义；新的战略结论；用户批准或验收状态；任务完成结论。
