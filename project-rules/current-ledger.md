# `current.md` 编写规则

## 1. 文件用途

`current.md` 是根目录下的当前 TODO 和阶段性进展记录。它与 `final-strategy/` 共同组成台账。它不负责定义新的项目架构或战略。

新任务只有在 yZz 明确授权记录后才能进入 `current.md`。

## 2. 固定结构

```md
## T-001 任务名称

### yZz 原话

> 用户原文

来源：记录文件和位置

### Agent 认为的任务

- 记录者：Agent 名称和日期
- 任务范围：
- 预期结果：
- 已知依赖：
- 尚未理解的内容：
- 执行授权状态：

### 状态演进

- 日期：可核查事件。【Agent 自动追加】
```

顺序固定为 `yZz 原话`、`Agent 认为的任务`、`状态演进`。

## 3. `yZz 原话`

1. 保持逐字内容，不改写语法、术语或拼写。
2. 提供来源路径和位置。
3. 多次原话共同限定任务时，按时间顺序列出。
4. Agent 解释不得混入该部分。

## 4. `Agent 认为的任务`

该部分记录 Agent 当时如何理解和操作化任务，可以包含范围、预期结果、依赖和未知项。它可能存在错误，因此必须与用户原话分开。

Agent 不得在该部分声称用户已经理解、批准或接受某项 Agent 推论。

## 5. 状态演进

状态演进按事情发生顺序追加。一次未完成、等待外部条件、发生阻塞或后续继续执行时，保留完整时间顺序。

Agent 可以自动追加：

1. 已执行的动作。
2. 命令、测试或实验的可验证结果。
3. 产物路径。
4. 当前等待的对象或条件。
5. 已确认的阻塞原因。
6. 原批准范围内的下一步状态。

每条自动追加内容都在末尾注明 `【Agent 自动追加】`。

Agent 不得自动追加：

1. 新任务、范围或优先级。
2. 对用户意图的解释。
3. 对任务目标的重新定义。
4. 新的战略结论。
5. 用户批准或验收状态。
6. 任务完成结论。

完成和移除任务需要 yZz 确认。在获得确认前保留任务及其状态演进。
