# 权限与批准规则

## 适用范围

本项目批准主体为 yzz。适用操作：安装或删除软件和环境；运行实验、训练、基准测试或会改变产物的脚本；新增、修改、移动或删除项目文件；Git 分支、提交、合并、推送和发布；对外发送消息、评论或文案；启动后台任务或自动化。以上操作需要明确执行授权。为回答问题进行的只读检查可以执行；只读检查不得扩展为状态修改。yZz 是当前项目中唯一已经建立明确批准权限的人。Agent 可以分析、建议、执行已批准工作和记录有限进展，Agent 的陈述没有用户决策权。未来参与者的共享方式和编辑权限尚未建立，当前规则不推定任何远程访问、直接编辑或独立批准权限。

## 规则

| 事件 | 含义 |
|---|---|
| 写入授权 | 允许把指定内容写入指定文件。 |
| 执行授权 | 允许执行指定操作。 |
| 内容批准 | 确认某项方案、结论或文本。 |
| 结果验收 | 确认指定范围的结果达到要求。 |

四类事件按对象与范围分别判断，任何一项不自动推出另一项。yzz 已在文档维护规则中明确授权策略获准后的自动同步、既有任务事实追加与索引摘要，以及平台规则中的经验脚本维护；这些有明确依据的权限按各自边界执行。

沉默、未纠正、Agent 标签与预选选项不能代替 yzz 表态。既有明确授权继续适用，后来的明确纠正和范围限制按实际对象处理。

## 操作与记录

先核对请求及授权。AGENTS 必须先有起草请求、再有具体文字确认，按新部署与旧更新的明确模式处理。current 的执行授权与建立条目许可分开。Computer Use 的具体提问要求只在 Codex 的自动化目录查阅。

有实际缺口时提出具体问题，已授权独立工作继续。当前范围与来源：2026-08-31，yZz 明确批准开始执行项目文档重组、联合审计修补和 Git 保护修复。授权范围以 `docs/sessions/2026-08-30-project-governance-audit-design-4df76da1/conversation.md` 中已经形成的方案及其后续用户纠正为准。该授权不包含环境安装、模型训练、性能测试、外部发布或新的技术设计决策。

本项目批准识别细则沿用迁移前规则：

1. 记录用户使用“同意”“批准”“可以写入”“就按这个”“替换到文件”等明确语言时的具体对象和范围。
2. “继续讨论”“我理解了”“先看看”“或许”“我不确定”等表达不构成批准。
3. 用户沉默、没有纠正或继续提出下一问，不构成批准。
4. 后来的明确纠正、否决或范围限制覆盖此前表述。
5. Agent 自己的“已经决定”“共识”“已定稿”等标签不能证明用户批准。
6. 工具调用、后台工作流、总结和文件中的现有文字不能自行证明用户同意。需要回到用户原话。
7. 写入 current 不构成任务执行授权。允许 Agent 修改文档不构成对 Agent 新增结论的批准。任务执行完成不构成用户验收。
