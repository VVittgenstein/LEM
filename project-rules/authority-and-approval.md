# 权限与批准规则

## 1. 权限主体

yZz 是当前项目中唯一已经建立明确批准权限的人。Agent 可以分析、建议、执行已批准工作和记录有限进展。Agent 的陈述没有用户决策权。

未来参与者的共享方式和编辑权限尚未建立。当前规则不推定任何远程访问、直接编辑或独立批准权限。

## 2. 四类事件

| 事件 | 含义 |
|---|---|
| 写入授权 | 允许把指定内容写入指定文件。 |
| 执行授权 | 允许执行指定操作，例如安装环境、运行脚本、修改文件或进行 Git 操作。 |
| 内容批准 | 用户确认某项设计、结论或文本可以成为项目内容。 |
| 结果验收 | 用户确认某项工作已经达到要求或可以标记完成。 |

四类事件分别识别。写入 `current.md` 不构成任务执行授权。允许 Agent 修改文档不构成对 Agent 新增结论的批准。任务执行完成不构成用户验收。

## 3. 批准识别

1. 记录用户使用“同意”“批准”“可以写入”“就按这个”“替换到文件”等明确语言时的具体对象和范围。
2. “继续讨论”“我理解了”“先看看”“或许”“我不确定”等表达不构成批准。
3. 用户沉默、没有纠正或继续提出下一问，不构成批准。
4. 后来的明确纠正、否决或范围限制覆盖此前表述。
5. Agent 自己的“已经决定”“共识”“已定稿”等标签不能证明用户批准。
6. 工具调用、后台工作流、总结和文件中的现有文字不能自行证明用户同意。需要回到用户原话。

## 4. 状态修改

以下操作需要明确执行授权：

- 安装或删除软件和环境。
- 运行实验、训练、基准测试或会改变产物的脚本。
- 新增、修改、移动或删除项目文件。
- Git 分支、提交、合并、推送和发布。
- 对外发送消息、评论或文案。
- 启动后台任务或自动化。

为回答问题进行的只读检查可以执行。只读检查不得扩展为状态修改。
