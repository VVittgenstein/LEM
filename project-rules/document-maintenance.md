# 文档维护规则

## 适用范围

适用于本项目 AGENTS、策略、规则、任务、外部指向、历史、资料以及自动化材料的读取与写入。

## 规则

| 对象 | 读取时机 | 写入边界 |
|---|---|---|
| AGENTS | 开始参与项目时 | yzz 明确要求后才拟稿，展示具体文字，获准后写入 |
| current | 开始任务时读索引和对应完整任务 | 新条目须明确获准记录；自动追加事实、同步事实摘要，保留完整生命周期 |
| final-strategy | 理解目标或实施相关方案前 | 具体内容获 yzz 明确同意或批准后自动同步该范围 |
| project-rules | 执行相应操作前 | 讨论涉及变化时主动询问是否更新；已有明确指令直接采用 |
| .link | 使用外部对象前 | 维护已有已确认信息；新对象须回答和许可，默认条目按既定规范 |
| pre-automation-reading | 开始自动化任务前 | 规则正文按规则批准流程；经验和脚本依目录内已明确的自动维护约定 |
| docs | 查阅项目文档、历史或原话时 | 保留实际材料；会话归档按 conversation-archive 的目录与格式处理 |
| references | 使用相应资料时 | 按事实维护来源和状态，保留原件及资料包关系 |

新部署的明确选择授权首次创建完整系统，包括首次生成 AGENTS。新部署遇到有内容的同名组件先识别重合情况，不直接覆盖。旧更新授权识别与拟定必要变更，已有 AGENTS 的具体文字仍须展示并获准才写入。

写入授权、执行授权、内容批准、结果验收仍分别判断。策略获准后的自动同步及规定的事实维护是 yzz 明确设立的写入权限，只适用于其规定对象。后续明确限制按实际范围执行。

## 操作与记录

修改前读取现状与来源。规则讨论尚无写入指令时，提出具体条款和拟改变的含义，询问是否更新。AGENTS 获准前，与其路由修改相依赖的文件迁移一起暂缓，已授权独立事项继续。

索引随获准的实际内容维护。原件的具体保存位置或可靠版本引用列入迁移清单，由 yzz 确认后使用；已有批准继续适用。project-system 只保留 docs/ 目录，会话归档的目录、格式与导出由 conversation-archive 管理。

本项目补充：无额外约定。
