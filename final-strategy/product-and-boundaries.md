# 产品、范围与边界

## 1. 产品需求

以下需求依据 yZz 在 2026-08-26 的产品表述、2026-09-05 的结果目标讨论，以及 2026-09-06 对 L1 数据标准、有限范围与显著地形的更正。来源与适用范围见本节和 `sources.md`。2026-09-09，显著地形的要求退出 MVP，见第 1.2 节。

1. 产品形态为 Minecraft Java Edition 模组。模型层保持引擎独立，Minecraft 是首个使用端。
2. 生成地形需要具有真实感和多样性。水文合理性、性能和 LOD 作为独立属性明确要求与评价依据。
3. LOD 兼容属于强制要求。Distant Horizons 是 MVP 的集成目标。
4. 性能和调度属于核心需求。系统支持预生成、服务器负载变化下的动态调度、远端 GPU 生成和玩家客户端参与计算。
5. 群系模组兼容属于强制要求。实现应尽量保留原版参数驱动的群系选择路径。

来源：既有产品要求见 `docs/2026-08-28-strategy-cascade-pipeline-and-probe-48979f05/conversation.md:160`；真实感、多样性与独立属性的后续表述见第 1.1 节所列用户消息。

模型最终生成真实地形是产品目标。1A 研究通过 Fastscape 及必要辅助手段获得项目所需数据的完整方法；Fastscape 的直接输出可以作为中间数据，其适用性结合后续处理、训练用途和模型验证判断。方法范围见 `architecture-dataflow.md` 第 4 节。数据生成中的“真实”按 2026-09-07 的三个概念判断：需要过程真实与地学合理，不要求历史真实；模型学到的是符合这两者的地形长什么样子。定义与衔接规则见 `architecture-dataflow.md` 第 4.1.3 节。

### 1.1 真实感与多样性

Minecraft 是首要使用场景，模型保持引擎独立。当前数据需要支持模型生成可持续探索的有限海洋大陆，并表达完整样本内部的海岸、内陆、山地、水系和环境组织。

海岸至山地的示例路径包含：玩家从海洋抵达宽广且延伸的沙滩海岸，远处可以看到积雪高山；水流形成河流并汇入海洋。沿河向内陆行进，经过广阔平原，再进入地势逐渐变陡、植被发生变化的山地，沿途遇到支流。该路径用于说明数据需要支持的地形结构及环境关系。海中出生、雪山融水和沿途树木变化属于示例情景，每份样本无需重复同一场景。

| 内容 | 数据需要表达的结构与关系 |
|---|---|
| 海岸 | 具有横向延伸和区域范围，玩家能够沿岸观察与移动。 |
| 平原 | 具有面积和延续性，沿河进入内陆时能够经过广阔的低坡区域。 |
| 山体 | 具有整体范围，远处可见的高山在接近过程中逐渐呈现坡面、山谷及周围结构。 |
| 河流与水系 | 海洋、河口、平原、山地和支流可以沿同一条探索路径共同出现，河流连接不同区域。 |
| 沿途环境 | 地势、坡度、水系与地表环境的变化和所在区域具有空间联系。 |

地形和环境必须具有足够的横向范围，使玩家能够接近、进入、持续穿行并越过地形。环境边界与变化方式符合现实中可以成立的空间关系，没有统一的平滑要求。具体延伸距离、行进时长和环境变化频率保持定性。

多样性尽可能在单个大陆内部成立，并同时包含：

1. 内容的丰富性：尽可能广泛的地形、地貌和 Minecraft 群系。
2. 空间组合的丰富性：这些环境具有多种相邻、分隔和连接关系。
3. 探索路径的丰富性：沿不同方向移动可以经历不同变化，例如沿海进入高地、海洋接近岛屿。
4. 各类环境自身的区域尺度：丰富程度与较长跋涉、地域延伸和自然变化共同成立。

真实感、多样性、水文合理性、性能和 LOD 分别定义与评价。水体与高程、河流连接等关系可以作为材料研究的检查对象；单独完成水文目标讨论不构成材料复评和方法研究的前置条件。地貌例子没有形成固定必选或排除清单；雪、水流、植被和群系如何由模型通道、辅助算法与 Minecraft 集成共同表达，仍需方法研究与验证。

### 1.2 显著地形与特殊点

数据生成方法需要能够主动创造宏伟山峰、低谷、海岸等特殊点与记忆点，并同时满足第 1.1 节的自然性、区域尺度、空间关系与多样性要求。山、谷、河等类别的覆盖需要与这种显著地形表现共同考虑。

yZz 用“一块大陆，有山有谷有河，但是很平淡，山可能就1000多米这种”说明希望改进的结果表现，并明确继续保留自然等要求。该反例未设定高度下限、统一峰谷高差、每份样本的数量或出现频率。显著地形的具体生成规则、空间分布与评价方式需要在 1A 中研究确定。2026-09-06，yZz 将“宏伟的特殊地形”直接定义为足够多样化的高峰、峡谷等特殊地形，对应第 4 号子任务的问题 6，并继续保留自然性与尺度要求；原话见 `current.md` T-009。问题 6 于 2026-09-09 撤销。

2026-09-09，yZz 撤销问题 6，表述不再要求“宏伟的特殊地形”，该要求不在 MVP 中；经 yZz 同日批准，本节“主动创造宏伟山峰、低谷、海岸等特殊点与记忆点”的要求整条退出 MVP，保留为后续可能的要求；反例原话与自然性等要求保留。原话见 `current.md` T-010。

来源：2026-09-05 的探索、尺度与多样性原话见 [`MVP 与数据目标讨论`](../docs/sessions/2026-09-05-lem-mvp-world-data-goals-9041c977/conversation.md)；2026-09-06 六点数据标准、补充反例及写入要求逐字保存在 [`current.md` T-009](../current.md#t-009-1a-数据生成方法研究)，源 JSONL 位置及有效分支见 `sources.md` 第 1、2 节。

## 2. 项目范围

### 2.1 MVP 范围

- 当前模型研究、数据生成与训练范围为 L1，目标为有限面积的海洋大陆。
- Distant Horizons 是唯一已确定的 MVP LOD 目标。
- 更高分辨率数据训练不属于当前 MVP，暂不开展；既有 L2、L3 及 10m 到 1m 转换方案保留为后续内容。当前 L1 输出到 Minecraft 的具体尺度转换与集成方法仍需确定。
- 方块化层负责把模型通道转换为游戏方块、群系参数和其他游戏数据。

L1、L2 和 L3 的精确定义见 `architecture-dataflow.md`。

当前大陆 MVP 的理想 L1 数据形态为：

1. 每份数据覆盖 500 km×500 km，完整包含大陆及其海域；海岸、内陆、山地和水系等空间组织共同处于同一份样本中。当前 L1 设置为 500×500 像素、1 km 格距。
2. 数据外围有一圈海洋，内部大陆区域的位置不必居中，陆地可以由不连续部分组成，也可以包含内海等海陆结构。
3. 批量生成许多不同样本，每个大陆内部尽可能具有第 1.1 节所述的真实感与环境多样性。
4. L1 数据需要主动创造第 1.2 节所述的宏伟山峰、低谷、海岸等特殊点与记忆点，同时保留自然等要求。具体构造方法、高程、相对高差、范围、位置和出现频率尚未确定。本条要求于 2026-09-09 由 yZz 撤出 MVP，见第 1.2 节。

500 km指完整数据域，海陆比例没有固定为60%。当前初始水下台地的二维形状采用用户选定的World Orogen平面分区与整组选区Gibbs方法，512分区、外围3层完整分区禁选，规则见 [水下台地二维形状](architecture-dataflow.md#platform-mask)。50%至60%是初始台地占整个数据域的面积偏好，允许偏离；34个参考陆块提供形状参考，不要求严格复现其全部统计分布。

数据4与数据1已于2026-09-12由yZz确认完成，包含台地掩膜、深浅海完整地块分配、固定剖面与相关起伏构成的初始海底，以及单一年代海平面曲线。初始台地与周边均在海平面以下，后续区域抬升与其他活动另行接入；当前参数及输入输出见 [已验收四阶段](architecture-dataflow.md#initial-input-stages)。三层禁选的实际宽度随分区几何变化，初始剖面按域内可用空间截取。T时刻的外围海洋与陆地不触界继续作为单独的演化检验对象；终态海洋带最小10 km的既有约定保留在该范围内。

当前 MVP 已确定为有限的海洋大陆，每份 L1 样本的地理范围内包含目标大陆及相关空间关系，调查和数据生成仅覆盖 L1。此前无限大地图生成的安排退出当前范围。训练样本尺度与模型可靠生成范围之间的关系仍需验证。

来源：同一归档的用户消息 64、67、69、71、74、76，以及 2026-09-06 六点数据标准和最终写入要求。当前范围以 2026-09-06 用户更正为准，原话见 `current.md` T-009。

### 2.2 当前不在 MVP 范围内

- Voxy 集成。开始前需要确认实际 API 和许可条件。
- 无限大地图生成和行星尺度的 LEM 组织方式。
- L2 数据调查、生成与训练，以及更高分辨率数据训练。
- L3 模型训练和真实 LiDAR/DEM 数据管线。

### 3.2 项目工作范围

1. 当前研究通过 Fastscape 及必要辅助手段生成 L1 所需数据的方法，并验证高程、水文及地貌过程通道的因果关系与一致性。研究范围包含广泛检索、借鉴、组合、改造和研发，受到项目能力与时间约束。
2. 先训练高程 L1，再训练高程与汇水面积联合 L1；其他生成通道逐项确认。
3. 当前验证 L1 输出与 Distant Horizons 的 LOD 请求接口，多尺度模型输出的连接保留后续身份。
4. 实现预生成、缓存、负载调度和远端计算流程。
5. 在保留群系兼容路径的前提下使用地貌过程通道。

## 5. 水文与地貌过程通道

Terrain Diffusion 的已知水文问题构成本项目水文方向的背景。2026-08-26 的记录包括论文局限、TD-mc issue #84、#115、#217 和 #240，以及社区后处理讨论。

当前批准的模型顺序是先训练只有高程的 L1，再训练联合生成高程和汇水面积的 L1。汇水面积是第一项水文生成通道。其他生成通道尚未确定，每次增加通道都需要单独确认并验证。

流向接收节点索引、上游计算顺序和流量分配索引只参与 LEM 内部运算。流域编号用于验证和统计。`rock_type__id` 用于 Landlab 内部材料管理。K、D 和其他 LEM 参数只参与训练数据生成、参数验证和结果复现。L1 与 L2 的训练和推理均不接收 K、D。

联合生成方向的目标是让模型同时生成高程和汇水面积，并检查从生成高程重新计算的汇水面积与模型生成汇水面积之间的一致性。

该方向的有效性尚未通过 E2 验证。任何“已经解决水文一致性”的表述都不成立。

## 6. LOD 与性能

### 6.1 LOD 目标

Distant Horizons 按需要取得适用数据。当前需要验证 L1 输出如何支持有限大陆的 LOD 展示，具体数据接口、分级与尺度转换尚未确定，由 E3 核对。既有多尺度模型输出及其与 DH 层级的映射保留为后续方案。

### 6.2 性能来源

性能策略包括：

- 预生成与缓存。
- 服务器负载较低时推进有限大陆范围内的预生成与缓存，负载较高时暂停后台生成。
- 在独立 GPU 设备上生成地形数据，CPU 服务器读取结果并执行方块化。具体调度与缓存划分需要结合有限大陆确定。
- 按距离取得适用的 LOD 数据；当前 L1 的具体处理方式由 E3 验证，多层模型按需计算保留后续身份。
- 在满足验证要求后评估玩家客户端计算节点。

跨硬件结果能否逐字节一致尚未验证。玩家节点提交结果前必须先定义模型版本、推理后端、精度、算子版本、采样器、序列化和验证协议。

Landlab 与 Fastscape 的项目环境已经建立。2026-09-03 已执行 LEM 侧导入验证、最小运行和 1 km 网格性能基准，当前 Fastscape 使用 Fortran 后端的直接 API。适用设置和实测结果见 `validation-risk-status.md` 第 3、9.4 节；具体方法的开发、验证与数据生成成本仍需结合其配置评估。

## 7. 群系兼容

默认集成路径使用模型输出的高程、气候和地貌通道形成原版群系选择所需参数，并继续调用原版参数驱动的群系选择流程。该方向的目的如下：

1. 保留数据包和通过原版参数表工作的群系扩展的接入位置。
2. 避免把默认群系选择固定为项目自己的封闭分类器。
3. 允许项目地貌过程通道作为可选增强输入。

具体参数映射和第三方模组兼容范围必须通过实现测试确认，当前不作兼容保证。

## 8. 合规边界

以下规则源自 2026-08-26 的调查，发布前需要按当时的许可证和平台条款重新核验。

1. 项目名称不得使用 “Terrain Diffusion” 造成来源混淆。
2. 使用 MIT 代码、权重或派生工程时保留相应版权和许可证文本。
3. Voxy 集成在取得适用许可和稳定接口前不进入 MVP。
4. 参考 LGPL 项目时核对实际复制、链接和分发方式产生的义务。
5. Distant Horizons 的具体依赖 artifact 和许可证在发布前逐项核验。
6. L3 使用真实 DEM 或 LiDAR 前，逐项核验数据源的使用、训练和分发许可。
7. Minecraft 模组的销售、捐赠、Patreon、提前访问和权益设计按实施时有效的 EULA 与 Usage Guidelines 单独核验。
