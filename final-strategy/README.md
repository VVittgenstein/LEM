## 策略摘要

1. 产品形态是 Minecraft Java Edition 模组。模型通过 ONNX 等通用格式保持引擎独立，Minecraft 是首个使用端。
2. 地形结果需要具有真实感与多样性：海岸、平原、山地与水系具有足够范围和相容的空间关系，玩家能够持续探索，并在同一大陆内经历丰富的地形、地貌和群系变化。主动创造宏伟山峰、低谷、海岸等特殊点与记忆点的要求于 2026-09-09 由 yZz 撤出 MVP，保留为后续可能的要求；自然性等要求不变。水文合理性、性能和 LOD 分别定义与评价。
3. Distant Horizons 是 MVP 的 LOD 集成目标。当前 L1 输出如何提供适用的 LOD 数据，以及后续多尺度模型的层级映射，分别通过验证确定。
4. 性能依赖预生成、缓存、负载调度和远端 GPU 计算。当前有限大陆 L1 的单次推理性能需要实测，多层模型按需生成保留后续身份。
5. 群系兼容属于产品要求。默认集成应保留原版参数驱动的群系选择路径。
6. 当前 MVP 的模型研究、数据生成与训练范围为 L1。生成目标为有限的海洋大陆：每份样本覆盖 500 km×500 km，陆地与海域共同处于完整数据域中，外围有一圈海洋；内部大陆可偏离中心、由不连续陆地组成并包含内海。每份样本共同包含海岸、内陆、山地和水系等空间组织，批量形成不同样本，并尽可能在每个大陆内部呈现丰富环境。海陆比例未固定。L2、L3 及更高分辨率训练保留为后续范围，当前暂不开展。
7. 当前优先开展 1A：在项目能力和时间范围内，不利用 DEM 反推，通过广泛研究、借鉴、合成、改造与必要的研发，获得通过 Fastscape 及辅助手段生成 L1 所需训练数据的完整方法，支持模型生成具有真实感与多样性的有限海洋大陆（显著地形的要求于 2026-09-09 退出 MVP）。当前调查与数据生成仅覆盖 L1。已有材料继续保留，依据当前目标复评用途、证据和覆盖，并继续广泛搜索。沿用论文与实验、项目与文章、讨论与想法的三级优先级，同时纳入官方文档及跨类别的真实性评价依据。Fastscape 的直接输出按其在完整方法中的用途验证。1A 条件未满足时，依据具体缺口评估 1B-1 至 1B-3；方法、数据与模型结果按阶段验证。2026-09-06 起，1A 第 4 号子任务曾按六个有依赖顺序的问题推进；2026-09-09 yZz 将任务重定义为数据与参数生成管线，六个问题结构被取代：原问题 1、2 为里程碑 1，即海陆组织；原问题 3、5 为待定义与测试的验收维度；原问题 4 由地学合理与过程真实承担；原问题 6 撤销。1A 包含用该管线生产一定数量的示例数据，正式生产训练集为 1A 的后续任务。数据生成中的“真实”按三个概念判断：需要过程真实与地学合理，不要求历史真实。2026-09-08 确定的方法框架为三类输入、陆地区域与地质活动清单，一次运行生成，产物按 T 时刻的统计检验判断；测试阶段的执行约束为 8 个独立样本并行、每样本 1 核、单样本完整实际用时不超过 180 秒，实际生成的用时预算未定。2026-09-08 至 2026-09-09 补充第 1 类初始高程与海平面、第 4 类陆地区域的生成规则与校准方式；2026-09-09 补充第 3 类过程参数的现状、补齐工作线与 n 的处理，并否决最小配置运行；同日确定第 2 类为五种成陆活动、每份样本全有、按独立系统计数并按第五类规则叠加；第 5 类的角度容差并入代理计算、程序化规则只作思路、争议分支取观测值或按样本随机；跨类决定为每份样本运行到抽定的模拟时长 T 且不设指标型结束、多流向加沉积项加海洋模块、T时刻的外围海洋带与陆地不触界检验；初始水下台地二维形状现采用World Orogen平面分区与整组选区Gibbs抽样，512分区、外围3层禁选，50%至60%为软面积偏好（2026-09-11选定）。详见 `architecture-dataflow.md` 第 4.1.2 至 4.1.6 节，任务记录见 `current.md` T-010。2026-09-09 前置任务 F、G、H 交付并合并，其分布的采用方式与三处更正写入第 4.1.5 至 4.1.6 节。
2026-09-12，yZz确认数据4与数据1完成，当前已验收台地掩膜、海域类型分配、初始海底高程及单一年代海平面曲线四阶段。入口、参数与边界见 [已验收输入阶段](architecture-dataflow.md#initial-input-stages)。数据2、3、5与统一LEM接入、终态验证继续推进，完整1A与E1尚未完成。

8. L1 验证顺序包含两个模型版本：先训练只有高程的 L1，再训练联合生成高程和汇水面积的 L1。L2 数据生产属于后续范围，两个 L1 阶段通过不自动启动 L2。
9. K、D 和其他 LEM 参数只参与数据生成、参数验证和结果复现，不进入 L1 或 L2 的训练与推理。
10. 当前使用 L1 的 `data1000m`。既有 L2 数据族 `data10m`、`data10mds10`、`data10mds100` 及其训练推理关系在 `architecture-dataflow.md` 中保留为后续方案。
11. 教师模型只用于训练。每个模型层级在全部部署场景使用同一版本的蒸馏后模型。
12. E0 至 E4 是当前批准的验证顺序。所有实验仍需要执行授权。
13. LEM 工具性能已在 1 km 网格实测（2026-09-03）：fastscapelib-fortran 每步 70 ms，Landlab 三种配置 1988 至 9895 ms。工具实现差异、fastscape 单流向例程的洼地抬升和 Python 层不可用见 `validation-risk-status.md` 第 9.4、9.9、9.10 节。
14. 数据生成以 fastscape 线为主要管线，Landlab 用于对照与能力核对（2026-09-03 确定，见 `validation-risk-status.md` 第 4.3 节）。
