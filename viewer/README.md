# 地形查看器

Windows 入口为项目根目录的 `launch_terrain_viewer.bat`，使用 `lem-env-win` 环境。

## 使用

1. 打开单个 `.npy`、包含多通道数组的目录，或 31415 查看器使用的 `.flem` 文件。声明在同目录 `meta.json` 中的单文件会连同数据集一起打开。
2. 左右各有一个显示位，每个显示位均可选择 `2D Map`、`3D Surface` 或 `3D Voxel`。同类视图可以同时显示。点击显示位右上角的关闭按钮后，另一个显示位占满区域；通过 `View → View 1 / View 2` 恢复，保留各显示位的参数与相机位置。至少保留一个显示位。
3. 点击显示位的标题、画面，或使用左侧 `Editing display`，选择当前调整的对象。通道、色带、颜色级数、显示采样和相机状态分别保存。
4. `Colour levels` 控制颜色分级；体素视图中的 `Height levels` 控制垂直高程分档。后者默认 36，可输入 2 至 4096；修改后重新生成当前体素网格。数值使用普通文本框，编辑期间可以删空、追加或全选替换，按 Enter 或离开输入框后校验并应用。无效值会标红并保留原已应用值。
5. `Vertical scale` 默认 1。已知格距和高程单位时，水平 1 km 与垂直 1 km 使用相同场景长度。改变高度级数会调整每层厚度，地形总高差和显示比例保持一致。0 表示沿用主线的自动垂直放大，并在画面中显示实际倍数。
6. 水位优先读取数据；缺失时采用 0 m 默认值。界面显示值的来源。数据明确声明无水时遵循该声明；关闭自动读取后可以输入仅用于显示的水位。
7. `Material appearance` 使用原查看器的草、土、石、雪等外观规则。默认的数据通道着色与主线图例一致，汇水面积使用对数分级。材质规则描述显示外观。
8. 两个三维表面可以开启 `Sync two surface cameras`。其他组合分别控制相机。

原始数组保存在数据模型中；`Max display size` 控制显示采样上限，默认 512。500×500 数据默认逐格显示。读取到的格距决定水平采样距离；缺少格距信息时沿用默认间距，并在体素视图注明物理尺度尚未核实。

体素数组已解除固定512 MiB分配上限，索引及体素计数使用64位类型。数组按显示网格的列数×行数×（高度级数+4）字节分配，另需列属性、网格及显存；重建时旧画面仍保留，会增加峰值内存。实际可显示规模取决于机器资源。尺寸、数值范围与分配长度的溢出检查继续保留。

体素相机保留原 C++ 实现的环绕与飞行模式：

| 操作 | 输入 |
|---|---|
| 环绕旋转、平移、缩放 | 左键拖动、中键或右键拖动、滚轮 |
| 飞行移动、升降、加速 | WASD、Space / Shift、Ctrl |
| 飞行方向、画面缩放 | 鼠标拖动、滚轮 |
| 切换相机、重置 | M、R，或左侧控件 |
| 材质或数据着色 | C 切换；1 为材质，2 为高程，3 为汇水面积，4 为侵蚀速率；缺失通道会提示 |
| 状态、性能、参考网格 | H、F3、G，或左侧控件 |
| 剔除、帧率上限 | F、V，或左侧控件 |
| 文件、材质配色、全屏 | L、P、F11 |

按键作用于已激活的体素显示位；侧栏输入优先，输入数字不会触发材质或通道切换，切回侧栏时释放移动按键。环绕相机可以缩放至单个水平格距的 5% 距离，非等距网格使用较短格距，并设场景长度 0.005 的下限；滚轮缩放采用乘法步进。窗口切换、退出及后端异常分别处理。单个原生进程异常时，另一个显示位继续使用；重新选择体素视图可以重启该显示位。

Fly模式中，滚轮向前放大、向后缩小，通过改变垂直视角实现，飞行位置和移动速度保持。视角范围为1°至90°，重置相机恢复45°；缩放状态在修改显示参数、关闭及恢复显示位时保留。

## 构建 C++ 后端

当前实现保留 J31415 的 C++17 / raylib 核心。每个体素显示位启动一个原生进程，通过 Qt 原生窗口容器嵌入。源码位于 `lem_viewer/voxel/native`，构建产物位于忽略的 `viewer/build`。来源与修改边界见 [THIRD_PARTY.md](lem_viewer/voxel/THIRD_PARTY.md)，数据和进程接口见 [PROTOCOL.md](lem_viewer/voxel/PROTOCOL.md)。

需要现有的 CMake 3.20+ 与 C++17 工具链；Windows 使用 Visual Studio 2022 C++ Build Tools。脚本通过 PATH 或 vswhere 发现 CMake。Python 依赖仍由原 BAT 启动器管理。

已有 raylib 源码时，向 `viewer/scripts/build_voxel_viewer.py` 传入 `--raylib-source` 及其目录。需要获取固定版本时，传入 `--download-cache` 及符合本机规则的下载目录。raylib 5.5 的提交和源归档哈希在脚本中固定；解压和编译发生在 `viewer/build`。

首次准备好依赖后，重新构建并运行 C++ 检查：

```powershell
.\lem-env-win\Scripts\python.exe viewer/scripts/build_voxel_viewer.py --test
```

日常启动使用原 BAT，无须重新编译。后端缺失时，体素显示位会给出构建说明。后端路径也可通过 `LEM_VOXEL_BACKEND` 指定。

## 验证

Python 回归：

```powershell
.\lem-env-win\Scripts\python.exe tests/run.py --group viewer
```

真实窗口检查要求已构建后端、可用的桌面与 OpenGL：

```powershell
.\lem-env-win\Scripts\python.exe tests/run.py --group viewer_native
```

该检查覆盖九种显示组合、两个体素进程、高度级数与比例、键盘及焦点、数值编辑、显示位关闭与恢复、窗口尺寸及最小化恢复、异常退出和进程回收。参数 `--display-size 512` 可用于检查完整 500×500 示例，示例数据须已在本地保存。C++ 核心检查包含非等距网格、平坦与负高程、无效值、水位、精度变化、相机缩放、分配长度及溢出检查。
